# Node advisories accepted with a reason and a revisit condition.
#
# One `GHSA-…` per line, followed by why it is accepted. Anything not listed
# here fails `just audit`. This file is the reason `pnpm audit --audit-level`
# is NOT lowered: a whole severity class going quiet would hide advisories
# nobody has read.

GHSA-g7r4-m6w7-qqqr
    esbuild <0.28.1 — the development server responds to any origin, so a page
    a developer visits while `vite dev` is running can read its responses.

    Why it cannot be fixed here: esbuild reaches this repository only through
    `spikes/marko-stream-resume` -> `@marko/run@0.11.8` ->
    `esbuild-plugin-browserslist@2.0.0`, whose peer range is `~0.27.0`. A
    tilde range does not admit 0.28.x, so moving esbuild means moving the
    `@marko/run` pin — and that pin is what E0's resumption and payload
    measurements were taken against. A pnpm override was tried on 2026-08-06
    and does not take, for this reason.

    Why the residual risk is acceptable: the exposure is the *dev server*.
    Nothing in this repository runs `vite dev`; the spike runs
    `marko-run build` and serves the built output, and `just ci` does not
    invoke Vite at all. No production artifact contains esbuild.

    Revisit: when `@marko/run` releases a version depending on
    `esbuild-plugin-browserslist` with an `^0.28` range, or when ADR-0002's
    deletion condition retires Marko at E7.

GHSA-vfj7-8cjw-p6xm
    braces <=3.0.3 — a deeply nested brace pattern exhausts the stack (a
    denial of service). No release is patched: 3.0.3 is the latest, and the
    advisory lists no fixed version (checked 2026-10-07, ADR-0244).

    Why it cannot be fixed here: braces reaches this repository only through
    `spikes/marko-stream-resume` -> `@marko/run@0.11.8` -> `@marko/vite` ->
    `fast-glob` -> `micromatch`, the build's file globbing.

    Why the residual risk is acceptable: the patterns it expands are the
    spike's own build globs, never input from a request, and no production
    artifact contains it.

    Revisit: when braces publishes a fixed release, when `@marko/vite` stops
    depending on micromatch, or when ADR-0002's deletion condition retires
    Marko at E7.

GHSA-pfhg-q3qv-9q6r
    SvelteKit <3.0.0 — enhanced forms on routes accepting double-slash paths
    can navigate to an external origin (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-pfhg-q3qv-9q6r

    Why accepted temporarily: the only @sveltejs/kit dependency is the
    undeployed E14 benchmark baseline, pinned to 2.70.3 under ADR-0120 for a
    controlled agent comparison. It uses use:enhance with named ?/add and
    ?/clear actions on /stores/[storeId], not a catch-all route accepting
    double-slash paths. This allowance does not establish that 2.70.3 is safe
    for general use or permit exposing the benchmark to untrusted traffic.

    Revisit: when E14-E chooses baseline versions, before exposing the
    baseline outside the local harness, or if a catch-all/enhanced action is
    introduced. Upgrade SvelteKit and its adapter to compatible 3.x releases
    and rerun the three-store contract; remove this allowance on migration.

GHSA-27mw-82g8-phjj
    SvelteKit <3.0.0 — untrusted cache-control passed to setHeaders while
    prerendering can inject markup into the generated page (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-27mw-82g8-phjj

    Why accepted temporarily: the same undeployed, locally exercised E14
    baseline has no prerender setting and does not call setHeaders or forward
    a request-supplied cache-control value. Its only configured adapter is
    adapter-node for the benchmark contract. This exception is not a claim
    that all SvelteKit 2.x applications are unaffected.

    Revisit: at E14-E, before deploying or exposing this baseline externally,
    or if prerendering/setHeaders is introduced. Upgrade to compatible
    SvelteKit >=3.0.0, rerun the contract and remove this allowance.
