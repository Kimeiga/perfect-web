================= WHAT THE CHALLENGE WORK KEEPS FINDING ========

  Six defects so far, none reachable from the 44 fixtures:

  1. A COMPILER PANIC. A constructor pattern whose arity disagreed
     with its declaration desynchronized the pattern row from the
     type list. Every rule in the invocation reported nothing.
  2. Privacy depended on the SPELLING PATH: `let same = token` lost
     the label. Replaced with value/dataflow propagation.
  3. A wrong library contract: `Stores.find` returned `Result`,
     which is `get`'s type — and R-008's own annotation was what
     established the return type the rule read.
  4. A correctness check that went SILENT, not wrong, when member
     identity was ambiguous. The by-name fallback is deleted.
  5. My own bad witness: a "gap" in the exhaustiveness checker that
     did not exist. The witness used constructor names its type did
     not have, so it tested the compiler on a program that did not
     typecheck. Found by the arity rule added the same hour.
  6. A LATENT FALSE POSITIVE. `let cart = query Cart(session)` did
     not parse as one expression, so every page declaring a query
     dependency was reported for reaching the database while
     rendering. R-004 carried it the whole time — it is caught for
     its declared invariant, so the extra diagnostic sat in the
     output unexamined. It took a file whose job is to be VALID to
     make it visible.

  Note what 5 and 6 have in common with each other and not with the
  rest: they were found by writing programs that must be ACCEPTED.
  A suite of things that must be rejected cannot find them.

  3. NOT "the language is sound".

     keywords, the phase permission matrix, and one module name for
     `on:` attributes.

     fixtures changed; docs/CORPUS.md has a row for each.
  6. NOT "P0 is publishable". Per the architect's readiness
     conditions, every invariant a headline claim demonstrates must
     be challenge-tested. Six of the eight are not yet.
