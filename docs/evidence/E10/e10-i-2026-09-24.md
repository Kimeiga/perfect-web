# E10-I: a Pleris-compiled command runs through the E8 host, 2026-09-24

Raw output: [e10-i.txt](e10-i.txt), produced by `just e10-i`. The artifacts are
[store.page.add_to_cart.wasm](store.page.add_to_cart.wasm) and
[store.page.clear_cart.wasm](store.page.clear_cart.wasm), produced by
`just e10-component`. Decision record:
[ADR-0032](../../DECISIONS/ADR-0032-compiled-components.md).
Environment: Darwin arm64 (Apple M2 Pro), rust 1.97.1, wasmtime 47.0.4,
wit-component / wit-parser / wasm-encoder / wasmparser 0.257.1.

## The obligation, and the closing condition

> Compile `add_to_cart` through the production Pleris→component backend and
> execute it through the E8 host, **with no alternate Rust closure path**.
>
> E10-I is met when a `.pw`-authored command runs as a component through
> `pw_host::engine::call_within` and the Rust closure path is deleted rather
> than left beside it. — `docs/EVIDENCE_LEDGER.md`

## What runs

```text
command add_to_cart(item: MenuItemId, quantity: PositiveInt) -> Result<Cart, CartError>
{
    Carts.add(current_session(), item, quantity)
}
```

`examples/store/app.pw` → `pw check` → Backend IR → core module (Canonical ABI,
every number from `wit-parser`) → `wit-component` → a 4,221-byte component
whose core module is 423 bytes. Its imports, read from the artifact:
`pw:host/session#read` and `store:data/carts#add`. The world also declares
`clear` and `current`, which the component does not import.

Through `pw_host::engine::call_within`, with the host's own operations:

```text
the host saw: [("pw:host/session#read", []),
               ("store:data/carts#add", [String("session-7"), String("cortado"), S64(2)])]
the command returned: [Result(Ok(Some(Record([("lines", List([Record([
    ("item-id", String("cortado")), ("quantity", S64(2)),
    ("unit-price", Record([("minor-units", S64(450))]))])]))]))))]
```

The session came from the host. The item and quantity came from the caller.
The result was lifted by Wasmtime out of the component's own linear memory,
where `carts#add`'s lowering had written it.

## Controls

| control | result |
|---|---|
| the data layer answers `Err(cart-expired)` | the command returns it unchanged |
| a node without `database.write<Carts>` | admission refuses, naming the capability |
| the contract without the write | **the engine** refuses: "component imports instance `store:data/carts`, but a matching implementation was not found in the linker" |
| a granted import the host does not implement | refused, rather than linked to a stub |
| one unit of fuel | "wasm trap: all fuel consumed by WebAssembly" |
| `carts#add` returning `result<domain-store, ..>` (identical at the core level) | the encoder refuses to connect it; the audit refuses the real artifact against that world |
| the committed `.wasm` vs a fresh build | byte-identical (`evidence_is_current`) |

All five of the store's commands and queries compile to audited components:
`Cart`, `Menu`, `Store`, `add_to_cart` and `clear_cart`.

## The closure is deleted

`spikes/own-renderer/server`'s `add_to_cart` and `clear_cart` now:

1. admit the compiled artifact against its real imports (`imports_of`, where
   the audit used to be given an empty list);
2. run it through `call_within`, with the session operation and
   `store:data/carts` as the deployment's data layer;
3. commit the data layer's staged write and its event in one
   `materializer.command`, only if the component returned `Ok`.

`the_commands_run_as_compiled_components` holds the deletion structurally.
`a_failing_command_commits_neither_state_nor_event` holds ADR-0019 through the
component's own result.

**Browser suite.** Recorded by `just e10-browser` in
[browser-suite.txt](browser-suite.txt), against commit `1209a94`: **Chromium,
Firefox and WebKit, 258 of 258, in three consecutive full runs.** The store
page's Add and Clear buttons reach the compiled commands.

The host's disk filled during this work, and macOS purged `~/Library/Caches`,
including every Playwright browser build. The browsers were reinstalled once
space was released and the run was recorded then.

One fix came out of the browser runs, and it is recorded because of how it was
found. The first version compiled each component on every call, building a
Wasmtime engine and running Cranelift over the whole component per click, and
admission compiled it again to read its imports. Under the suite's parallel
load, one Firefox `keyed-list` test failed in each of two full runs, a different
test each time; alone, that suite passed 14/14 three times. The same suite on
the untouched baseline (`145588e`, in a separate worktree) passed 258, 258, then
failed one Firefox `keyed-list` test in the third run. So the flake predates
E10-I, and per-call compilation made it more frequent.
`pw_host::engine::Prepared` now compiles a component once. The dev server also
reads each artifact's imports once. Authority is still decided per call, so a
linker is always built from that call's `Granted`. With that change: the recorded 258, 258, 258 above.

## Not claimed

- **Resumable handler bodies are not compiled.** The browser's handler posts
  the pressed instance's address and the literal quantity. The command is
  compiled; `add_to_cart(item.id, PositiveInt(1))` in the page is not.
- **The data layer is not Pleris.** `store:data/carts` is the deployment's
  (`owner: external` in the contract). Replacing it is NEXT step 10.
- **The backend supports a narrow set.** Straight-line bodies, import calls,
  scalar constants, and values passed through flat or in their canonical
  layout. Constructing records, reading fields, calling another compiled
  declaration, branches and memory constants are each refused by name.
- **The invocation region is provisional.** It is not the language's memory
  model.
