# E10 gate item 2: compiled semantics against a reference, 2026-09-25

Raw output: [oracle.txt](oracle.txt), produced by `just e10-oracle`. The
harness is `compiler/pw-conformance`, the one crate that links the compiler and
the engine. It ships nothing, and ADR-0020's boundary holds for the host and
the servers.

## The obligation

> Semantics match the oracle tests. — charter §14 M10 gate
>
> Differentially compare server behavior with generated Koka/Rust reference
> implementations. — task 9

## The method

Every compiled server declaration runs beside an independent Rust statement of
what it means, against the same generated data layer:

| declaration | reference |
|---|---|
| `store.page.add_to_cart` | read the session; call `carts#add(session, item, quantity)`; return its answer |
| `store.page.clear_cart` | read the session; call `carts#clear(session)`; return its answer |
| `store.page.Cart` / `Menu` / `Store` | call the one data-layer operation with the argument; return its answer |
| `kiokun.page.Lookup` | `get(word)`; for `Some(e)` whose `redirect` is `Some(t)`, return `get(t)`; for `Some(e)` without one, `Some(e)`; for `None`, `None` |
| `kiokun.page.Search` | call `index#search(q, 20)`; return its answer |

The two must make the same calls, in the same order with the same arguments,
and return the same result, over **300 generated cases per declaration**.

Inputs and the data layer's answers are generated from the component's own
types, read from the artifact by Wasmtime (`component_type()`). Nothing
describes the types separately, so nothing can drift from them:

- strings: empty, ASCII, CJK, kana, emoji, punctuation, Latin with accents, and
  runs of up to 3,000 `語`;
- `s64`: including `i64::MIN` and `i64::MAX`;
- nested records, lists, options, results and variants.

For `Lookup` the data layer is a generated table whose redirects name another
entry, the entry itself, or a word that is absent. So chains, stubs to stubs
and stubs to missing words all occur.

## Result

```text
store.page.add_to_cart   300 cases agree
store.page.clear_cart    300 cases agree
store.page.Cart          300 cases agree
store.page.Menu          300 cases agree
store.page.Store         300 cases agree
kiokun.page.Lookup       300 cases agree
kiokun.page.Search       300 cases agree
```

**The oracle can disagree.** Three references, each wrong in one detail a
miscompilation could share, are each caught:

- `Search` passing a limit of 21;
- `Lookup` not following the redirect;
- `add_to_cart` not reading the session.

## What else is an oracle here

- **Koka** is the effect oracle (E9-K conformance) and runs the pure subset
  (`just spike-pw-to-koka`, in CI). None of these seven declarations is pure:
  each calls the data layer. So Koka is not run on them, and a Rust reference
  is the charter's other named option.
- `compiler/pw-conformance/tests/variants.rs` runs the lookup on
  hand-written cases and checks each refusal by its exact reason.

## Not claimed

- **The references are written from the source**, by the same author as the
  compiler work. They were written from each declaration's meaning, not from
  its lowering. What would catch a shared misreading is a second author or
  Koka, not this test.
- **Only the compiled set is covered.** Pure computation (arithmetic,
  `if`, string operations) is not compiled yet, so it is not compared.
