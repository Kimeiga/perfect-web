# Milestone 0 — Repository bootstrap, research matrix, specification corpus, and feasibility spikes

**Status: GATE PASSED against charter v2, with one documented shortfall** (2026-08-05)

> **Charter version:** executed first against v1 (four spikes), then **reopened**
> when charter v2 was adopted mid-session. v2 expands Milestone 0 to **six**
> spikes and adds the §7.5A layout-phase model. Both new spikes were built and

Charter §14 requires each milestone document to contain: question, rationale,
scope, non-goals, deliverables, tests, gate, measured result, risks discovered,
next decision.

---

## Question

> Can the proposed semantic architecture be made concrete enough that accepted
> and rejected programs define the project before a large implementation exists?
> Can Koka, Marko, Wasmtime, and the Mac toolchain interoperate sufficiently to
> justify the bootstrap plan?

**Answer: yes to both, with six measured corrections to the bootstrap plan** —
four to the Koka/Marko/Wasmtime assumptions, and two from charter v2's new
layout-phase and incrementality questions.

## Rationale

Charter §14 M0: *"The greatest early risk is not code volume. It is discovering
that the assumed integration boundaries do not exist. Spikes make that visible
before the repository becomes committed to a fragile architecture."*

That is exactly what happened. All six boundaries exist, and several assumptions
about them turned out to be wrong in ways that change later milestones.

## Scope

Repository bootstrap; toolchain pins; `just doctor` / `just bootstrap`; version
verification against primary sources; technology matrix; ADRs; the accepted /
rejected corpus; **six** isolated feasibility spikes; non-goals.

## Non-goals

No compiler. No `pw` grammar. No runtime. No benchmarks. No browser automation.
No Linux CI beyond a stated gap. The spikes are deliberately **isolated** — none
of them is wired to any other, because Milestone 0 answers "does this boundary
exist", not "does this system work".

### The shortfall, stated plainly

Gate item 7 passes on macOS. It does **not** pass on Linux, because there is no
Linux CI. Charter §13.5 and §20 both require it — to catch case-insensitive
filesystem assumptions and to make component builds reproducible — and §3.6
requires license and vulnerability checks in CI, which also do not run.

This does not block Milestone 1: nothing in Milestone 1 is platform-sensitive
(Koka libraries, effect handlers, a compile-test harness). It **would** block
Milestone 3, where generated file paths and asset casing start to matter. It is
therefore the first item in `docs/NEXT.md` rather than a reason to hold the gate.

Recorded as risk R11, currently the highest-likelihood open risk.

## Measured result

### Spike 1 — koka-js-interop

- ADTs and effect handlers compile and run on Apple Silicon. Generated `.mjs`
  imports into Node with **no adapter and no bundler**.
- **Effect rows are machine-readable without a fork**, from the `.kki` interface
  file: `calculate-subtotal !{}` vs `load-store !{database-read, trace-effect}`
  vs `main !{console}`, and handlers visibly discharge effects
  (`load-store-for-js !{}`). This closes charter risk R2 and resolves
  Milestone 1 task 8 a milestone early.
- 16 Node tests pass, including the negative cases that pin the gaps.

**Four things that do not work as the plan assumed** — see
`docs/KNOWN_LIMITATIONS.md`: exhaustiveness is enforced only for `exn`-free
functions; single-field value structs are erased; `Nothing`/`Nil` are both
`null`; the generated `is_*` predicates are not validators.

### Spike 2 — marko-stream-resume

```text
route            html    html.gz  downloaded JS  inline JS  script tags
/static           588        357          0 B        0 B    0
/stream          1669        986          0 B      849 B    3 inline
/counter         1721        930       3921 B      350 B    1 ext + 1 inline
/counter-large  16537       2468       3927 B      356 B    1 ext + 1 inline

streaming:  shell 3.1 ms | estimate 408.2 ms (400 ms) | recs 1206.0 ms (1200 ms)
resumption: HTML grew 9.6x -> route-specific client JS grew 1.03x
```

The charter §18.4 static budget is met **exactly** (zero script tags). Streaming
is real and out-of-order. Resumption does not scale with document size. The
emitted HTML is already a document-parts representation (`<!--M_*2 a-->` anchors
+ inline resume manifest), giving Milestone 7 a concrete oracle.

Honest qualification: the *streamed* route needs 849 bytes of inline patch shim.

### Spike 3 — wasmtime-component

All four capability checks pass on the `no_std` component:

```text
check:ambient=pass   imports = ["perfect-web:store/stores@0.1.0"]   (exactly one)
check:granted=pass   lookup(store_47)="found:store_47:Blue Bottle", host called twice
check:denied=pass    instantiation REFUSED, diagnostic names the missing import
check:fuel=pass      traps on a 1,000-unit fuel budget
```

Charter §10.2's claim — *"a component without an imported capability cannot use
it"* — is enforced, not conventional.

**WASI 0.2, not 0.3** (`@0.2.9`): the charter's fallback branch taken on
measurement (ADR-0008). **`std` costs 14 ambient WASI imports** and 8.3× the size.

### Spike 4 — compiler-diagnostic

Charter §16.3's target diagnostic reproduced from real parsed spans, with both
the boundary span and the label-origin span, the inferred label, and legal
alternatives — plus a stable error code the charter's prose version lacks.
18 unit tests, including "malformed input never panics" over 10 inputs.

`--explain` derives placement from visibility + cache partition, and asserts its
output leaks no generated-file paths (a Milestone 2 gate item, made testable now).

### Spike 5 — layout-phase-scheduler (charter v2)

Charter v2 §20 says explicitly: *"build forced-layout instrumentation in
Milestone 0."* Built, and the effect size is the largest measured anywhere in
this milestone:

```text
elements   mode     median ms   checksum     LoAF long frames
400        thrash    79.1        59600       7
400        phased     0.3        59600       0        -> 264x
1200       thrash   678.6       178800       7
1200       phased      0.8      178800       0        -> 848x
```

Identical checksums: same work, different ordering. Thrashing is *superlinear*
(3x the elements costs 8.6x the time); phase scheduling is flat.

Also measured: ResizeObserver feedback loops are detectable via the browser's
`ResizeObserver loop completed with undelivered notifications` error;
`contain` + `content-visibility` made a 3,000-row subtree's build-and-layout
**4.18x faster** (23.8 ms -> 5.7 ms) — but made a forced layout after an
unrelated host mutation marginally *slower*.

**The charter's preferred signal is unavailable:** `forcedStyleAndLayoutDuration`
is `undefined` on `long-animation-frame` entries in Chrome 150. Long-frame count
plus `blockingDuration` is the working proxy.

### Spike 6 — bonsai-incremental-model (charter v2)

The OCaml toolchain **does** install on Apple Silicon, so no blocker was recorded
— though it took four attempts (`timeout` is not a macOS builtin; `OPAMYES` does
not authorize system packages; `pkgconf` missing). opam resolved **bonsai
v0.16.0**, not the available v0.17.0.

Incremental delivers what charter §9.5 asks for:

```text
5 unrelated updates       -> expensive node evaluated 1 time
1 related update          -> evaluated 2 times
same value written again  -> still 2 (cutoff)
```

**Where incrementality stops, from installed source.** Bonsai's `dune-package`
declares `ui_incr`, `incr_map`, `virtual_dom`, `js_of_ocaml`. Rendering ends at
`virtual_dom/node.mli`:

```ocaml
val create : previous:node -> current:node -> t
```

`Patch.create ~previous ~current` compares two complete trees — precisely what
charter §8.4 forbids. Bonsai's DAG avoids recomputing *values* and then hands the
result to a tree diff. This is the clearest possible instance of charter v2's new
risk, *"fine-grained updates are mistaken for layout safety"*: genuinely
fine-grained at the computation layer, entirely silent about layout.

## Risks discovered

Five new risks, none of which were in charter §20, all found by running things.
Full detail in `docs/RISK_REGISTER.md` R13–R17.

- **R13** Ambient authority arrives through the language runtime, not the app.
- **R14** Measuring only entry chunks under-reports client JS by 20×.
- **R15** Semantic checks on parser-recovered syntax produce noise.
- **R16** The temporary renderer can silently miscompile (`>` in attributes).
- **R17** Benchmarks are incomparable to the charter's assumed M3 Max / 64 GB.

Plus **R3**: Koka's semantics are weaker than the bootstrap plan assumed
(exhaustiveness, nominal types, null).

## Next decision

**Proceed to Milestone 1** (Koka semantic kernel), with three amendments forced
by Milestone 0's evidence:

1. **Milestone 1's compile-fail cases for exhaustiveness must declare total
   effect rows.** Otherwise Koka accepts them and the tests pass vacuously
   (finding F-8). This is a correctness requirement for the harness itself.
2. **Milestone 1 must not claim nominal domain types are enforced.** Charter
   §14 M1 task 2 asks for "opaque wrappers" for `StoreId`, `Money` and friends;
   Koka gives compile-time-only nominality that is erased at the boundary. The
   milestone should document the gap rather than assert the guarantee — the
   charter's own task 7 already sets this precedent for linearity.
3. **`node/kki.mjs` graduates from spike to tool.** It is the mechanism by which
   Milestone 1 demonstrates its gate item *"every effectful example has a visible
   inferred effect"*. It should move to `tools/` and gain tests.

**Do not** start Milestone 2 (parser/grammar) concurrently. Charter §0.

**Before Milestone 3**, close the Linux CI gap (gate item 7's shortfall).
