# E3 — Marko rendering adapter, streaming SSR, first resumption

**Status: PARTIAL.** Four of six gate items pass. The two open ones both need
one thing `pw` cannot yet express: a delayed region.

## Question

> Can the custom language produce a modern streamed and resumable HTML
> application before building a renderer from scratch?

**Answered so far: yes for static and interactive routes.** Two applications
written entirely in `.pw` generate Marko, build, serve, and pass in three
browser engines. Streaming is not answered — see the gate.

## Measured

Both routes are generated from `.pw`; nothing under `src/routes` is authored.

| route | HTML | gzip | `<script src>` | inline | client JS | gzip |
|---|---|---|---|---|---|---|
| `/static` | 346 B | 222 B | **0** | **0** | **0 B** | **0 B** |
| `/counter` | 1,109 B | 672 B | 1 | 393 B | 4,314 B | 2,300 B |

The static route ships **no JavaScript at all** — no script tag, no request.
That is the byte-level item M3 asks for, met from `pw` source rather than from
a hand-written template.

The counter ships 4.3 kB for one button on a page that is otherwise inert
markup. That is the charter §8.5 claim the measurement exists to test, and it
is Marko's behaviour measured through `pw` (ADR-0017), not `pw`'s own.

## Gate

Charter §14 M3 lists six items.

| # | gate item | result |
|---|---|---|
| 1 | Static page usable with JavaScript disabled | **PASS** — asserted with JS actually off, in all three engines |
| 2 | Static page emits zero application JS, ideally zero framework JS | **PASS** — zero of both; no script tag and no JS request |
| 3 | Delayed content streams without blocking the shell | **NOT MET** — `pw` cannot express a delayed region yet |
| 4 | Counter interaction works without whole-page re-execution | **PASS** — a server-rendered node is marked, the counter is clicked twice, and the marker survives |
| 5 | All three Playwright engines pass | **PASS** — 21 tests × Chromium, Firefox, WebKit |
| 6 | Generated code is not exposed in normal diagnostics | **PASS** — carried over from E2 (`explain_never_leaks_generated_paths`); `pw check` never names a generated file |

### Why item 3 is not met, precisely

Marko streams — E0 measured it, and `spikes/marko-stream-resume` shows a
1,200 ms region arriving after a 3 ms shell. The gap is **on the `pw` side**: a
delayed region needs a value that is not ready yet, and `pw` has no syntax for
one. `query`, `resource` and `task` are E4's concepts, and inventing an
`await`-shaped construct here to satisfy a gate would be building E4's design
inside E3's adapter.

The adapter refuses rather than approximates: a `{#each}` directive is skipped
with a reason today, and a delayed region would be too. That is deliberate —
an approximation renders, and a page that renders and is wrong is worse than
one that does not render.

**This item moves to E4**, where the resource model gives it a value to wait on.

## What implementing it found

**Markup was a token run.** It round-tripped and parsed the whole corpus and
was useless for rendering. Losslessness was never the hard part; structure was.

**Whitespace between inline elements is content.** The parser treated it as
trivia, so it never reached HIR and `<span>Espresso</span> <span>$3.50</span>`
rendered as `Espresso$3.50`. Fixing that exposed a second, subtler version: the
adapter used block layout on the assumption that "HTML collapses the newline
back to a space". **Marko strips whitespace between elements in a template**, so
it does not. The rule is now that whitespace containing a newline is formatting
and whitespace without one is content — which is exactly the distinction the
author made by writing them on one line.

**Only the browser found the second one.** The template-level test asserted the
template, and the template was fine. `docs/RISK_QUEUE.md` records the pattern:
a check that inspects the artifact one layer above the defect will pass.

**An ADR claimed a verification that had not happened.** ADR-0017's first
version said every mapping row was verified against a running Marko; the
parameter row was written from memory and the build rejected it. The correction
is recorded in the ADR itself.
