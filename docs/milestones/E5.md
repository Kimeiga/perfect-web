> Can the compiler reject invalid browser/edge/origin placement and cross-tenant
> or secret data flow before runtime?

## The design decision that mattered

Charter §7.8 lists the labels and then says the thing that decides everything:

> Do not force all labels into a simplistic total order. Some are incomparable.

`Session<a>` and `Session<b>` are not ordered. A total order would rank one
tenant above the other and let the flow through in one direction — the
cross-tenant leak, produced by the checker meant to prevent it.

So a label is a **set of restrictions**: `Public` is the empty set, join is
union, and `a` flows into `b` only when `b` carries at least `a`'s restrictions.
Incomparability falls out rather than being bolted on, and the join of two
tenants is *stricter than both*, which is the conservative answer.

Placement is solved in the same direction. Rather than asking "is this effect
allowed here?" — which needs a rule per effect per world and silently permits
anything nobody wrote a rule for — it asks **which worlds can satisfy everything
this body needs**. A body needing both the DOM and the database has no answer,
and the solver says so.

## What is deliberately not built

**Effect inference.** `R-001` — a network call inside a pure view — needs the
*callee's* effects, and nothing provides them. Guessing from the name would
produce a rule that fires on `fetch_store` and misses `load_store`, which is
worse than not having it. E9 owns inference.

**The label-introducing accessor table** in `check.rs` is a stand-in for library
signatures that do not exist. With a real library the checker reads
`current_organization()`'s declared return label instead. **The table is the
thing to delete when the library lands, not the rule that uses it.**

**Separate browser/edge/origin manifests** (task 7) and the **`unsafe` escape
hatch** (task 6) are unstarted. The escape hatch parses and lowers; nothing
checks its justification yet.

## What implementing it found

**An unmodelled capability must rule out nothing.** The first table granted an
unlisted family to no world, so a declaration using `log` or `resource` — neither
of which the table mentioned — was reported as having nowhere to run. Two corpus
files were "caught" that way: right file, wrong reason. The coverage number went
from 7 to 9 while nothing had been detected. Now anything not in the table is
available everywhere, because a checker must not reject what it has not been
taught. Recorded in `docs/RISK_QUEUE.md`.

**Placement is inherited.** A `fn` inside `component placement browser` runs in
the browser too. Checking each declaration alone missed the charter's opening
example — a database read inside a browser-placed component — because the effect
and the placement sit on different declarations.

**The corpus specifies the words, not just the codes.** The first diagnostics
said `database.read` where the file expects `database.read<Stores>`, and
`Secret<payments>` where it expects `Secret<Payments>`. Both are the same
capability and neither is the same text, and the text is what a developer reads.
